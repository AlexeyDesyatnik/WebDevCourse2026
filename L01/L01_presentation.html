►► КРЮЧОК

Полсекунды, в которые ты не заглядывал

Ты нажал Enter. Через полсекунды страница на экране. Откуда она взялась? На твоём компьютере её не было. Значит, за это время кто-то что-то у кого-то попросил.

►► ПОНЯТИЕ

Двое: тот, кто просит, и тот, кто хранит

  • Клиент — твой браузер. Просит и рисует.
  • Сервер — компьютер, который хранит файлы и отдаёт их.
  • Клиент спрашивает — сервер отвечает. Никогда наоборот

►► ПОНЯТИЕ

Как браузер находит нужный сервер

  • У каждого сервера есть числовой адрес.
  • Людям дали имена: school.ru.
  • DNS переводит имя в число — как телефонная книга.
  • Это происходит до основного запроса, за миллисекунды

►► ЖИВОЙ КОД

Разговор клиента и сервера словами

Так выглядит запрос и ответ, если записать их текстом. GET — «дай». 200 OK — «держи, всё в порядке»

Request URL: https://example.ru/index.html
Request Method: GET
Status Code: 200 OK

►► ПОНЯТИЕ

Четыре кода, которых хватит

  • 200 — всё в порядке
  • 404 — такой страницы нет
  • 403 — есть, но тебе нельзя
  • 500 — у сервера самого что-то сломалось

Страница — это не картинка. Это текст, который можно открыть

►► ЖИВОЙ КОД

Три слоя одной страницы

HTML — скелет. CSS — одежда. JavaScript — мышцы. Убери одежду — некрасиво. Убери мышцы — не шевелится. Убери скелет — нет ничего

<h1>Сколько раз нажали</h1>
<p id="out">Пока ни разу</p>
<button id="btn" type="button">Нажми меня</button>
<script>
  const btn = document.getElementById("btn");
  const out = document.getElementById("out");
  let count = 0;
  btn.addEventListener("click", () => {
    count = count + 1;
    out.textContent = "Нажатий: " + count;
  });
</script>

►► ИИ НА ЗАНЯТИИ

Промпт: три аналогии «клиент и сервер»

Ты объясняешь устройство интернета подростку 14 лет, который никогда не писал код.
Задача: придумай три разные аналогии для пары "клиент и сервер". Аналогии должны быть из повседневной жизни школьника — не из мира техники.
Ограничения: никаких технических терминов внутри самой аналогии; каждая аналогия не длиннее трёх предложений; не используй сравнение с рестораном и с почтой — они уже разобраны на занятии.
Формат ответа: нумерованный список из трёх пунктов. В каждом пункте сначала аналогия, потом отдельной строкой — в чём она НЕ работает, где сравнение ломается.
Критерии проверки: аналогия понятна без дополнительных объяснений; в ней ясно, кто просит и кто отдаёт; указано ограничение аналогии.

Проверить руками: роли различимы · понятно, кто просит · нет техтерминов внутри аналогии · есть строка про ограничение · понял бы одноклассник · нет фактической ошибки

Правило курса: сдаётся только то, что ты можешь объяснить

Глоссарий занятия 1

Клиент
Тот, кто просит: твой браузер. Отправляет запрос и ждёт ответ.
Сервер
Компьютер, который хранит файлы сайта и отдаёт их по запросу. Работает круглосуточно.
Запрос
Сообщение браузера серверу: «дай мне вот это».
Ответ
То, что сервер присылает обратно: файлы или сообщение об ошибке.
HTTP
Правила, по которым браузер и сервер разговаривают.
HTTPS
Тот же HTTP, но разговор зашифрован: посторонний в сети его не прочитает.
Код ответа
Трёхзначное число в начале ответа сервера. 200 — всё в порядке, 404 — нет такой страницы, 403 — нельзя, 500 — сломалось у сервера.
DNS
Служба, превращающая имя сайта в числовой адрес сервера. Телефонная книга интернета.
IP-адрес
Числовой адрес компьютера в сети.
Домен
Имя сайта словами, например school.ru.
HTML
Язык разметки: структура и смысл страницы. Скелет.
CSS
Язык оформления: цвета, размеры, раскладка. Одежда.
JavaScript
Язык поведения: реакция на действия пользователя. Мышцы.
Frontend
Всё, что происходит в браузере. Этому учит курс.
Backend
Всё, что происходит на сервере: данные, пароли, расчёты.
Fullstack
Разработчик, который умеет и то и другое.
DevTools
Инструменты разработчика внутри браузера. Открываются клавишей F12.
Консоль
Вкладка DevTools, куда браузер пишет ошибки.
Ментальная карта
Схема, где в центре главное понятие, а от него расходятся связанные.
