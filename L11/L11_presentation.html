►► ЗАКАЗ

«Я не знаю, кому отдавать пирог»

Марина Петровна с распечаткой: заявки с пустым именем, «ко скольки — завтра». Форма принимает всё подряд

►► ПОНЯТИЕ

Две проверки, две задачи

  • В браузере — помочь человеку не ошибиться
  • На сервере — не пустить плохие данные в систему
  • Одна другую не заменяет
  • Клиентскую можно обойти через DevTools — и это нормально

►► ЖИВОЙ КОД

Перехватываем отправку

  • Событие submit — на форме, не на кнопке
  • preventDefault() первой строкой
  • Дальше всё в твоих руках
form.addEventListener("submit", (event) => {
  event.preventDefault();
  // наша проверка
});

►► ТАК НЕЛЬЗЯ

Обработчик на кнопке

Форму отправляют тремя способами: мышью, Enter из поля, Enter на кнопке. Событие submit возникает во всех трёх. click — не всегда

►► ТАК НЕЛЬЗЯ

Пропустит Enter из поля

btn.addEventListener("click", (event) => {
  event.preventDefault();
});

Правило: форма — submit, не кнопка — click

►► ПОНЯТИЕ

Правила проверки решаются до кода

  • Обязательно ли поле?
  • Каким должно быть значение?
  • Что сказать, если не так?

Функция проверки возвращает текст ошибки или пустую строку — не true/false

function checkName(value) {
  if (value.trim() === "") return "Напиши имя";
  return "";
}

►► ТАК НЕЛЬЗЯ

Забыть .trim()

Три пробела — не пустая строка. Поле считается заполненным, заявка уходит без имени

►► ТАК НЕЛЬЗЯ

Пробелы пройдут

if (value === "") {
  return "Напиши имя";
}

Сообщение об ошибке — это инструкция, а не сигнал тревоги

►► ПОНЯТИЕ

Хорошее сообщение

  • «Ошибка» → «Напиши имя — как к тебе обращаться?»
  • «Некорректный формат» → «Класс пишется как 9А или 11Б»
  • «Значение вне диапазона» → «От 1 до 5 штук за раз»

Говори, что делать, а не что не так. Дай пример. Без крика

►► ЖИВОЙ КОД

Доступность: четыре строки

  • aria-describedby — в разметке, один раз
  • aria-invalid — из скрипта, когда ошибка
  • removeAttribute — когда исправлено
  • .focus() на первое неверное поле
errorBox.textContent = message;
input.setAttribute("aria-invalid", "true");
// и в CSS:
input[aria-invalid="true"] { border-color: var(--err); }

►► ВОПРОС

Когда проверять: при вводе, при уходе из поля или при отправке?

Обсуждаем вслух. У каждого варианта есть свои последствия

►► ПОНЯТИЕ

Момент проверки

  • При каждом нажатии — ошибка вспыхивает, пока человек печатает
  • При отправке — он сказал «готово», мы честно ответили
  • И при исправлении — но только после первой отправки
let wasSubmitted = false;
if (!wasSubmitted) return;

►► ТАК НЕЛЬЗЯ

Показать только первую ошибку

Человек с тремя ошибками отправит форму три раза. С каждым разом раздражаясь сильнее

►► ТАК НЕЛЬЗЯ

if (message !== "") {
  showError(input, errorBox, message);
  return;   // выход после первой
}

►► ЖИВОЙ КОД

Шесть полей без шести копий

  • Повторяющееся описываем данными
  • Обрабатываем одним циклом
  • Добавилось поле — одна строка в массив и одна функция
const FIELDS = [
  { input: "#name", error: "#nameError", check: checkName },
  { input: "#cls",  error: "#clsError",  check: checkClass }
];

►► ЗАЧЕМ

Рефакторинг

  • Переписать так, чтобы стало понятнее, а работало точно так же
  • Не добавляет возможностей и не чинит ошибки
  • Порядок: сначала работает → потом сокращаем → потом проверяем, что не сломалось

►► ПРАКТИКА

Что делаешь сегодня

  • Перехватываешь отправку формы предзаказа
  • Проверяешь шесть полей, показываешь все ошибки сразу
  • aria-invalid и фокус в первое неверное
  • Собираешь повторы в цикл
  • Тренажёр: два режима

Сделано, если: Enter из поля тоже работает, три пробела не проходят, все ошибки видны сразу, сообщения объясняют, что исправить

►► ИИ НА ЗАНЯТИИ

Промпт: убери повторы, не меняя поведения

Ты помогаешь провести рефакторинг кода начинающего разработчика.
Контекст: страница школьного буфета, проверка формы предзаказа. Чистый JavaScript, без библиотек. Ученик знает: функции, массивы объектов, filter/map/find, addEventListener, делегирование, textContent, classList. Не знает: классы, модули, асинхронность.
Задача: в моём коде повторяются одинаковые куски для разных полей формы. Предложи, как убрать повторы, сохранив поведение абсолютно тем же.
Ограничения: не меняй тексты сообщений об ошибках; не убирай preventDefault, .trim(), aria-invalid и постановку фокуса; не предлагай библиотеки, классы, модули и встроенную браузерную валидацию вместо моей; не сокращай так, чтобы стало непонятно четырнадцатилетнему; пиши по-русски.
Формат ответа: сначала список того, что именно повторяется, — не больше четырёх пунктов. Потом переписанный код. Потом таблица: что было, что стало, что при этом не изменилось в поведении.
Критерии проверки: поведение идентично исходному; все проверки на месте; количество строк уменьшилось; код читается без дополнительных объяснений.

Глоссарий занятия 11

Валидация
Проверка введённых данных до того, как их принять.
Клиентская проверка
Проверка в браузере. Помогает человеку не ошибиться. Её можно обойти, поэтому она не защищает.
Серверная проверка
Проверка на сервере. Защищает систему от плохих данных. Клиентскую не заменяет и не заменяется ею.
Событие submit
Попытка отправить форму. Возникает при всех способах отправки, включая Enter из поля.
preventDefault
Отмена стандартного поведения браузера. Для формы — отмена отправки и перезагрузки страницы.
.trim()
Обрезка пробелов по краям строки. Обязательна перед проверкой текстового поля.
Функция проверки
Принимает значение, возвращает текст ошибки или пустую строку.
Регулярное выражение
Шаблон для проверки текста. .test(строка) возвращает true, если строка подходит.
Сообщение об ошибке
Текст рядом с полем, объясняющий, что исправить. Не «ошибка», а инструкция.
aria-describedby
Атрибут в разметке: указывает id элемента, который описывает поле.
aria-invalid
Атрибут из скрипта: сообщает программе чтения, что поле заполнено неверно. Снимается при исправлении.
.focus()
Установка курсора в поле. Ставится в первое неверное поле после неудачной отправки.
form.reset()
Возврат всех полей формы к исходным значениям.
Рефакторинг
Переписывание кода так, чтобы он стал понятнее, а работал точно так же. Поведение не меняется.
Массив описаний
Данные о однотипных объектах (полях формы), позволяющие обработать их одним циклом вместо копий кода.
