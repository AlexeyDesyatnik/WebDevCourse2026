►► Проверим

Отправьте эту ссылку другу

file:///C:/Users/Ученик/Desktop/severny-pirog/index.html

у него не откроется ничего

►► Понятие 1

Что значит «опубликован»

  • файлы лежат на сервере
  • у места есть адрес
  • соединение защищено (https). Ни одно не про качество кода
file:///C:/...
https://ivanov.github.io/severny-pirog/

►► Понятие 2

Статический сайт

Сервер отдаёт готовые файлы и ничего не вычисляет. Поэтому: бесплатно, быстро, за пять минут. И поэтому же нельзя хранить общие данные

index.html  style.css  script.js  pie.svg  README.md

►► Понятие 3

CI/CD: публикация без рук

Настроили один раз → дальше каждый git push в main сам обновляет публичную версию. Отдельной команды деплоя нет

git commit -m "Вынес стили в style.css"
git push

Публикую прямо сейчас

Настройки репозитория → публикация из main → адрес выдан → открываем

►► Сюрприз

404 — файл по такому адресу не найден

►► Понятие 4

Три вида путей, один правильный

  • C:\Users\... — только у вас
  • /style.css — от корня сайта, а проект в папке
  • style.css — относительный, работает везде
<link rel="stylesheet" href="style.css">

►► Так нельзя

Три пути, которые сломаются

►► Так нельзя

Все три локально могут сработать и все три упадут после публикации

<link rel="stylesheet" href="/style.css">
<link rel="stylesheet" href="C:\Users\Ученик\style.css">
<img src="file:///C:/pie.svg" alt="">

►► Ловушка

Заглавные буквы

Windows: Pie.SVG = pie.svg. Сервер: это разные файлы. Отсюда — латиница, нижний регистр, дефис вместо пробела

git mv Pie.SVG pie.svg

►► Порядок в проекте

Стили — в отдельный файл

В index.html — одна строка <link>. В style.css — только правила, без тегов <style>

<link rel="stylesheet" href="style.css">

/* style.css */
:root { --pie-accent: #7CC142; }

►► Вопрос

Стилей нет, в консоли пусто. Почему?

файл на месте, путь верный, ошибок нет

<link href="style.css">

Обсуждаем вслух, ответ не показываем сразу

Откройте ссылку на телефоне

Не на компьютере. На телефоне. Прямо сейчас

►► ИИ в работе

Модель пишет README — вы отвечаете за правду

Дай факты списком и запрети выдумывать. Проверь: нет ли возможностей, которых у тебя нет; нет ли разделов про установку и сборку; ведёт ли ссылка на живой сайт

Контекст: я школьник, сделал учебный одностраничный сайт школьного
буфета «Северный пирог» на HTML, CSS и JavaScript без фреймворков
и без сборщиков. Проект опубликован по ссылке
https://<сюда свой адрес>/ и лежит в репозитории.

Что сайт умеет (это факты, ничего не добавляй от себя):
- меню из шести позиций рисуется из массива данных
- фильтр «сладкое / солёное» и сортировка по цене
- модальное окно с составом пирога
- форма предзаказа с проверкой полей
- «меню дня» с запасным вариантом, если данные не пришли
- тёмная тема, запоминается между визитами

Что сделано с помощью ИИ (тоже факты):
- сгенерирована иконка pie.svg, вручную убраны жёсткие width и height
- предложены варианты текста «о буфете», выбран один и сокращён

Задача: напиши README.md для этого проекта.

Ограничения:
- пять блоков в таком порядке: название и одна фраза о проекте;
  ссылка на опубликованную версию; стек; что умеет; что сделано
  с помощью ИИ;
- ссылка идёт сразу после названия, до всего остального;
- ничего не выдумывать: если факта нет в списке выше — его нет
  в README;
- не писать про установку, сборку, npm, зависимости и лицензию —
  их в проекте нет;
- «что умеет» — по одной строке на пункт, начиная с существительного
  или глагола, без слов «функционал», «реализовано», «современный».

Формат ответа: готовый текст README.md в разметке Markdown,
без пояснений до и после.

Критерии проверки: посторонний человек, прочитав README за минуту,
понимает, что это за проект и где на него посмотреть.

Проверить руками: ссылка на месте и живая · ни одной выдуманной возможности · нет разделов про установку и сборку · блок про ИИ конкретен · стек честный · ты можешь пересказать README своими словами

Правило курса: сдаётся только то, что ты можешь объяснить

Глоссарий занятия 15

Деплой (публикация)
Перенос файлов проекта туда, откуда их отдают всем желающим по адресу. После деплоя у сайта появляется публичная ссылка.
Статический сайт
Сайт из готовых файлов, которые сервер отдаёт как есть, ничего не вычисляя. Вся логика работает в браузере посетителя. Публикуется бесплатно и за минуты, но не может хранить общие для всех данные.
Хостинг статических сайтов
Сервис, который хранит файлы сайта и отдаёт их браузерам по адресу. На курсе используется тот, что встроен в платформу репозиториев.
CI/CD
Автоматическая цепочка «изменение → проверка → публикация», срабатывающая после отправки коммита. Настраивается один раз; дальше публикация обновляется сама после каждого git push в основную ветку.
Относительный путь
Адрес файла, отсчитываемый от текущей страницы: style.css, pie.svg, img/logo.svg. Работает и локально, и по любому адресу на любой платформе. Единственный вид путей, разрешённый внутри проекта.
Абсолютный путь
Полный адрес файла от корня диска (C:\Users\...) или от корня сайта (/style.css). Внутри проекта не используется: после публикации такой адрес не находится.
Статус 404
Ответ сервера «файл по такому адресу не найден». Виден в DevTools на вкладке Network. Главный признак ошибки в пути или в регистре имени файла.
Кэш браузера
Сохранённая копия уже загруженных файлов. Из-за него после публикации может показываться старая версия стилей; лечится обновлением с очисткой кэша (Ctrl+F5).
README.md
Файл с описанием проекта, который платформа показывает на главной странице репозитория. Пять обязательных блоков: название, ссылка, стек, что умеет, что сделано с помощью ИИ.
Markdown
Простой формат текста с разметкой: # для заголовков, - для списков, ** для полужирного. На нём пишется README.md.
