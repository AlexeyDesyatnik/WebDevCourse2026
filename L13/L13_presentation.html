►► Понятие 1

Репозиторий — папка с памятью

Обычная папка: удалил — исчезло навсегда. Репозиторий: всё зафиксированное можно вернуть. Внутри — скрытая папка .git, руками не трогаем

git init

►► Что видит Git

git status — главная команда

Три состояния файла: не отслеживается · изменён · зафиксирован. git status отвечает человеческим текстом, что происходит прямо сейчас

git status
Untracked files: index.html

►► Понятие 2

Коммит — снимок с подписью

Два шага: git add — положить в коробку. git commit — заклеить и подписать. Зачем два: чтобы разные правки шли разными коммитами

git add style.css
git commit -m "Стили буфета: карточка и кнопка"

►► Так нельзя

a71f0c3 работа

►► ТАК НЕЛЬЗЯ

Один коммит за занятие · сообщение «работа» · вернуться некуда: состояния «стили уже есть, модалки ещё нет» в истории просто нет

►► Правило

Что изменилось, а не что делал

  • предмет изменения
  • глагол
  • 5–72 символа
  • без «фикс», «работа», «правки»
  • без союза «и» дважды

►► Живой пример

История за полтора часа

Пять строк, каждая понятна без пояснений. Читается снизу вверх: каркас → стили → данные → поведение → README

git log --oneline
9f2c1a7 README: описание проекта
4b71e08 Модалка состава пирога
d3a0f52 Карточки из массива PIES
81ce4d9 Стили буфета
2ad60b1 Каркас страницы буфета

►► Смотрим

Ломаю и чиню за десять секунд

Удаляю скобку в script.js → страница белая, в консоли SyntaxError → одна команда → всё на месте

git restore script.js

►► Понятие 3

Ветка — черновик рядом с чистовиком

В main не экспериментируют. Рискованное — в ветку feature/имя. Не вышло — переключился обратно, проект цел

git switch -c feature/menu

►► Понятие 4

Удалённый репозиторий

Полная копия истории на сервере. Один раз — remote add. Каждое занятие — push. Публикация на занятии 15 идёт отсюда

git push -u origin main

►► ИИ в работе

Модель пишет сообщение — вы отвечаете за смысл

Дай модели список изменений и рамку: 5–72 символа, без «рефакторинг» и «оптимизация», что изменилось, а не что делал.

Контекст: я школьник, делаю учебный сайт школьного буфета на HTML, CSS
и JavaScript без фреймворков. Веду проект в Git. Пишу сообщения коммитов
по-русски.

Задача: сформулируй сообщение коммита для изменений, перечисленных ниже.

Изменения:
- в script.js добавлена функция sortByPrice, она сортирует массив PIES
  по возрастанию цены и возвращает новый массив
- в index.html добавлена кнопка с текстом «Сначала дешёвые»
- в style.css добавлено правило для этой кнопки

Ограничения:
- одно предложение, от 5 до 72 символов;
- описать, ЧТО изменилось в проекте, а не что делал разработчик;
- запрещены слова: работа, правки, фикс, рефакторинг, оптимизация,
  улучшение, архитектура;
- без точки в конце, без эмодзи, без английских слов кроме имён
  функций и файлов.

Формат ответа: три варианта сообщения, каждый на отдельной строке,
без нумерации и без пояснений.

Критерии проверки: я должен по сообщению понять, что появилось
в проекте, не открывая код.

Проверить руками: описано ли то, что ты правда сделал

Правило курса: сдаётся только то, что ты можешь объяснить

Глоссарий занятия 13

Репозиторий
Папка проекта, которая хранит все зафиксированные состояния своих файлов. Внутри неё лежит скрытая папка .git — это и есть память проекта.
Коммит
Зафиксированное состояние проекта с сообщением, датой и автором. К любому коммиту можно вернуться, даже если файлы с тех пор много раз менялись.
Сообщение коммита
Короткая строка, объясняющая, что изменилось в проекте. Пишется по правилу «что изменилось, а не что делал», длиной 5–72 символа.
Индекс
Промежуточная зона, куда командой git add кладут изменения перед коммитом. Позволяет зафиксировать не всё сразу, а только выбранные файлы.
Ветка
Отдельная линия истории, где можно менять файлы, не трогая основную версию. Основная ветка называется main.
main
Основная ветка проекта. В ней хранится рабочее состояние; эксперименты в неё не попадают напрямую.
Удалённый репозиторий
Полная копия репозитория на сервере платформы. Защищает проект от пропажи компьютера и служит источником для публикации сайта.
origin
Короткое имя адреса удалённого репозитория. Назначается один раз командой git remote add и дальше используется вместо длинной ссылки.
git status
Команда, которая человеческим текстом показывает, что сейчас происходит в проекте: какие файлы изменены, какие подготовлены, на какой ты ветке.
git restore
Команда, возвращающая файл к состоянию последнего коммита. Используется, когда правки ещё не зафиксированы, а проект уже сломан.
git revert
Команда, создающая новый коммит, который отменяет изменения указанного. Используется, когда плохое изменение уже попало в историю.
История проекта
Последовательность коммитов, по которой видно, из каких шагов собрался проект. Показывается командой git log --oneline.
