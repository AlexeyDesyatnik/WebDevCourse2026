Что подготовить до занятия

  • Пройти весь путь самому накануне, на своём тестовом репозитории: init → коммиты → ветка → push → открыть страницу репозитория в браузере. Особенно проверить вход в учётную запись платформы на школьных машинах: если авторизация не проходит, занятие встанет на двадцать минут.
  • Проверить, что Git установлен на всех машинах. Команда git --version должна отвечать номером версии. Установка на десяти компьютерах во время занятия невозможна.
  • Проверить, что у каждого есть учётная запись на доступной платформе репозиториев и что почта подтверждена. Список сверить заранее, за занятие до этого.
  • Заготовить карточку из десяти шагов (раздел 9, «Стартовая заготовка») — по одной на компьютер, бумажную. Переписывать команды с проектора медленно и с ошибками.
  • Заготовить резервный вариант: если платформа недоступна, занятие полностью проводится локально (шаги 1–9), а push переносится на начало занятия 14. Локальная часть — это 90 % содержания, срывать занятие нельзя.
  • Заготовить папку severny-pirog с рабочим сайтом буфета для тех, у кого файлы прошлых занятий потерялись.
  • Настроить в терминале крупный шрифт (не меньше 20) и светлую тему на время демонстрации.

Что вывести на экран

  1. Терминал, открытый в папке severny-pirog, крупным шрифтом.
  2. Проводник с включённым показом скрытых файлов — чтобы .git было видно.
  3. Браузер с открытым index.html (для демонстрации поломки и починки).
  4. Вторая вкладка браузера — страница удалённого репозитория.
  5. Файл script.js в редакторе — его ломаем на шаге 6 демонстрации.
  6. Тренажёр L13_trainer_git.html — открыть к 88-й минуте.

Где группа обычно застревает

  1. Терминал открылся не в той папке, и git init создал репозиторий на рабочем столе. Признак: git status выдаёт сотни строк. Готовое действие: научить читать строку приглашения терминала («какая папка написана перед знаком доллара?»), удалить лишнюю .git, перейти в проект и повторить. Разобрать это сразу на обходе 6–13 минут, до того как ошибка размножится по группе.
  2. «У меня Git сломался» — забыт git add. Признак: nothing to commit, working tree clean после commit. Готовое действие: не подсказывать команду, а попросить прочитать ответ Git вслух. В девяти случаях из десяти ученик догадывается сам, и это запоминается лучше подсказки.
  3. Авторизация на платформе при первом push. Признак: команда висит или просит логин и пароль, а пароль не подходит (платформы требуют токен вместо пароля). Готовое действие: заранее пройти этот шаг у себя, знать точную последовательность для вашей платформы и держать её на бумаге. Если у двух-трёх человек не выходит — не задерживать всю группу, перенести их push на начало занятия 14, а коммиты у них локально уже есть.

15. Домашнее задание и связь с проектом

Домашнее задание (20–30 минут)

Интернет нужен только на последнем шаге. Если дома его нет — первые три пункта делаются полностью офлайн, а push переносится на начало следующего занятия.

  1. Открой свой репозиторий и выполни git log --oneline. Выпиши в тетрадь самое плохое своё сообщение коммита и рядом напиши, как надо было. Одна строка на каждое.
  2. Внеси в сайт буфета одно небольшое улучшение — любое: поправь текст в подвале, добавь ещё один пирог в массив PIES, поменяй акцентный цвет. Сделай это в новой ветке feature/homework и зафиксируй одним коммитом с осмысленным сообщением.
  3. Сломай проект нарочно (удали закрывающую фигурную скобку в script.js), убедись, что страница белая, и почини командой git restore. Запиши в тетрадь, что было написано в консоли браузера, — дословно.
  4. Отправь ветку: git push -u origin feature/homework.

Сдаётся одной строкой в чат группы: ссылка на свой репозиторий. Проверять педагог будет по git log и списку веток, открывать код не потребуется.

Связь с итоговым проектом

Пункт ТЗ итогового проекта (Приложение 1 к программе):

«использование ветвления (разработка фич в отдельных ветках с последующим Pull Request)»

Сегодня закрывается первая половина этого пункта — ветвление. Вторая половина, Pull Request, — занятие 14. С сегодняшнего дня и до защиты действует правило: каждая новая функциональность итогового проекта делается в отдельной ветке.

Критерий из 30 баллов (Приложение 2):

«Культура работы с Git — 5 баллов: 10+ осмысленных коммитов, ветвление, PR»

Занятие даёт первые два элемента из трёх: осмысленные коммиты и ветвление. Десять коммитов не набираются за одно занятие — они накапливаются с сегодняшнего дня до занятия 23. Именно поэтому привычка коммитить каждые 15–20 минут закладывается сейчас, а не в модуле 9: начать вести историю за два занятия до защиты уже не получится.

Что переносится в занятие 15: удалённый репозиторий, созданный сегодня, — это тот самый источник, из которого пойдёт публикация сайта. Ученик без отправленного репозитория к занятию 15 не получит публичной ссылки, а это контрольная точка программы.
