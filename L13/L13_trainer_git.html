Глоссарий

Репозиторий
Папка проекта, которая хранит все зафиксированные состояния своих файлов. Внутри — скрытая папка .git.
Коммит
Зафиксированное состояние проекта с сообщением, датой и автором. К любому можно вернуться.
Индекс
Промежуточная зона: туда командой git add кладут изменения перед коммитом.
Ветка
Отдельная линия истории. Основная называется main; в ней не экспериментируют.
git restore
Возвращает файл к состоянию последнего коммита, если правки ещё не зафиксированы.
git revert
Создаёт новый коммит, который отменяет указанный. Нужен, когда плохое изменение уже в истории.
Карточка педагога
  • Навык: выбрать следующее действие в Git-ситуации; отличить restore от revert; сформулировать сообщение коммита по правилу «что изменилось».
  • Норматив: 15–25 мин на занятии (блок 80–88 мин). Это сценарий, не симулятор командной строки: настоящий Git — в практике раздела 9.
  • Типичные ошибки: один коммит «работа»; забытый git add; правка в main; revert вместо restore; голый git push новой ветки; союз «и» в сообщении.
  • Зачёт: тесты 2–11 не меньше 8 из 10 и зелёный тест 12 (три сообщения). Кнопка «Показать разбор» открывает все варианты. После трёх подсказок разбор открывается независимо.
  • Усложнение: восемь и больше коммитов без союза «и»; пара «поломка — revert» вместо restore.
  • Поддержка: разобрать ситуации 7 и 9 на проекторе; сообщения брать из карточки и объяснять вслух, почему выбран предмет изменения.
  • ИИ: промпт из занятия формулирует сообщение по списку diff. Руками: 5–72 символа, нет «рефакторинг/оптимизация», описано то, что ученик правда сделал.
