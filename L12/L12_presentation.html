►► КРЮЧОК

Я писал сверху вниз. Вывелось не так

В консоли: «начали», «закончили», «прошло ноль секунд», «прошла секунда». Хотя в коде порядок другой

console.log("1. начали");
setTimeout(() => console.log("2"), 1000);
setTimeout(() => console.log("3"), 0);
console.log("4. закончили");

►► ПОНЯТИЕ

Асинхронность

  • Запрос к серверу занимает время
  • Браузер не останавливается — иначе страница замрёт целиком
  • Он запускает долгое дело и идёт дальше
  • Результат обрабатывается, когда придёт

►► ТАК НЕЛЬЗЯ

Использовать результат, не дождавшись

Через полсекунды переменная изменится. Но вывод уже произошёл — там null

►► ТАК НЕЛЬЗЯ

let menu = null;
setTimeout(() => { menu = ["Калитка", "Рыбник"]; }, 500);
console.log(menu.length);   // ошибка

►► ПОНЯТИЕ

Promise: обещание результата

  • Результата пока нет, но он будет
  • Ровно два исхода: получилось или нет
  • resolve — получилось, reject — нет
  • Обещание можно вернуть из функции и передать дальше
return new Promise((resolve, reject) => {
  resolve(MENU);
});

►► ЖИВОЙ КОД

async и await

  • await — «подожди здесь результат»
  • Браузер при этом не заблокирован
  • async перед функцией обязателен
  • Код читается сверху вниз, как обычный
async function loadMenu() {
  const menu = await getMenu();
  renderMenu(menu);
}

Сеть работает. Сервер ответил. А данных нет

►► ПОНЯТИЕ

Проверять надо что ответил сервер

  • Для запроса код 404 или 500 — успех: ответ получен
  • В catch при этом ничего не попадёт
  • Код ответа проверяем вручную
  • throw бросает ошибку сознательно
if (!response.ok) {
  throw new Error("сервер ответил " + response.status);
}

►► ЖИВОЙ КОД

try, catch, finally

  • try — попробуй
  • catch — если сломалось
  • finally — в любом случае: сюда убираем индикатор
  • Без catch функция оборвётся молча, индикатор зависнет
try {
  const response = await getMenuFromServer(mode);
} catch (error) {
  renderMenu(FALLBACK.items);
} finally {
  btn.disabled = false;
}

►► ВОПРОС

Сколько состояний у экрана, который получает данные извне?

Обсуждаем вслух. Большинство назовёт одно или два

►► ПОНЯТИЕ

Четыре состояния

  • Загрузка — индикатор и заблокированная кнопка
  • Данные — то, ради чего всё
  • Пусто — ответ пришёл, данных нет
  • Ошибка — сеть или сервер подвели

Новички делают только второе

►► ТАК НЕЛЬЗЯ

Нет индикатора — нажмут пять раз

Две секунды тишины. Человек не знает, работает ли кнопка. Уходит пять запросов, результаты накладываются

►► ТАК НЕЛЬЗЯ

async function loadMenu() {
  const r = await getMenuFromServer("slow");
  renderMenu(r.data.items);
}

►► ЖИВОЙ КОД

Фолбэк: план на случай, когда сети нет

  • Константа с сохранённым ответом
  • При сбое показываем её
  • И честно говорим, что данные из копии
  • Пишется раньше запроса, а не «если останется время»
} catch (error) {
  renderMenu(FALLBACK.items);
  showNotice("Меню из сохранённой копии", true);
}

►► ТАК НЕЛЬЗЯ

Фолбэк без сообщения

Человек видит вчерашнее меню и думает, что оно сегодняшнее. Приходит за рыбником, которого не пекли

►► ЧЕК-ЛИСТ

Пять пунктов для любого запроса

  • 1. Отправили — показали загрузку, заблокировали кнопку
  • 2. Дождались — await в async-функции
  • 3. Проверили ответ — код ответа и пустой список
  • 4. Вывели данные — на страницу, а не в консоль
  • 5. Предусмотрели ошибку — catch, фолбэк, пометка

►► ПРАКТИКА · КОНТРОЛЬНАЯ ТОЧКА

Что делаешь сегодня

  • Меню приходит «с сервера», а не из кода
  • Четыре состояния интерфейса
  • Пять режимов проверки: работает, медленно, пусто, ошибка, нет сети
  • Тренажёр: два режима

Сделано, если: данные видны на странице; все пять режимов дают осмысленное поведение; при сбое — меню из копии с пометкой

►► ИИ НА ЗАНЯТИИ

Промпт: что может пойти не так

Ты составляешь список проверок для кода начинающего разработчика.
Контекст: учебная страница школьного буфета получает «меню дня» от сервера. Чистый JavaScript, без библиотек. Ученик знает: функции, массивы объектов, DOM, addEventListener, Promise, async/await, try/catch. В коде используется учебная функция вместо fetch, возвращающая объект с полями ok, status, data.
Задача: перечисли, что может пойти не так при загрузке данных, и что должен увидеть человек в каждом случае.
Ограничения: не предлагай библиотеки, axios, React и серверный код; не переписывай мой код; рассматривай только то, что видит пользователь на экране; не больше шести случаев; пиши по-русски.
Формат ответа: таблица из четырёх колонок — что случилось, что увидит пользователь без обработки, что должен увидеть, какой код это обеспечивает (одна-две строки).
Критерии проверки: перечислены как минимум сбой сети, ошибочный код ответа, пустой ответ и долгое ожидание; для каждого случая описано, что видно на экране, а не только что в консоли.

Проверить руками: все четыре случая перечислены · различает сбой сети и код ответа · описано, что видно на экране · нет советов про библиотеки · проверено в тренажёре · нет лишнего

Правило курса: сдаётся только то, что ты можешь объяснить

Глоссарий занятия 12

Синхронный код
Выполняется строка за строкой, по порядку. Всё, что ты писал до этого занятия.
Асинхронный код
Запускает долгое дело и не ждёт его, продолжая работу. Результат обрабатывается, когда придёт.
setTimeout
Отложить выполнение на указанное время. Самый простой пример асинхронности.
Promise
Обещание, что результат появится позже. Ровно два исхода: получилось или нет.
resolve
Вызвать, когда получилось. Передаваемое значение станет результатом.
reject
Вызвать, когда не получилось. Передаваемое значение станет причиной ошибки.
then / catch
Что делать при успехе и при неудаче обещания. Более старая запись.
async
Слово перед функцией, разрешающее использовать внутри await.
await
«Подожди здесь результат». Останавливает выполнение функции, не блокируя браузер.
try / catch
«Попробуй выполнить» и «если сломалось, сделай вот это».
finally
Блок, выполняющийся в любом случае: и при успехе, и при ошибке. Место для скрытия индикатора.
throw
Бросить ошибку сознательно. Нужен, когда сервер ответил кодом ошибки.
fetch
Встроенная функция запроса данных у сервера. Возвращает Promise.
response.ok
true, если код ответа 200–299. Проверять вручную: ошибочный код не попадает в catch.
response.status
Числовой код ответа сервера: 200, 404, 500.
JSON
Текстовый формат обмена данными. Похож на объект JavaScript, но это строка.
JSON.parse / JSON.stringify
Превратить текст в объект и наоборот.
Состояние загрузки
То, что видит человек, пока данных ещё нет: индикатор и заблокированная кнопка.
Состояние «пусто»
Ответ пришёл, данных нет. Не ошибка: сообщение спокойное.
Фолбэк
Запасной источник данных на случай, когда основной недоступен. В проекте обязателен и пишется раньше запроса.
Чек-лист запроса
Отправили → дождались → проверили ответ → вывели данные → предусмотрели сообщение об ошибке.
