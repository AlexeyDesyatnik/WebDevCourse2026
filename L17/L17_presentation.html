►► Найдите ошибку

Код красивый. Код не работает

const вместо var, понятные имена, ровные отступы, комментарий по делу. Одна минута — ищите

const sweet = pies.filterBy("kind", "сладкое");
const names = sweet.mapTo(p => p.name);
document.querySelector("#menu").innerText = names.joinWith(", ");

►► Понятие 1

Галлюцинация

Уверенно выданная неправда. Не выглядит как ошибка: аккуратный код, понятные имена, правильный комментарий. Уверенность тона не связана с правильностью

Только первую ошибку

►► Что покажет консоль

►► Признаки

Когда строку надо проверить

  • метод, которого не было на занятиях
  • слишком удобная сигнатура
  • имя из двух склеенных слов
  • обращение к полю ответа, которого ты не видел

Протокол аудита: пять шагов

1 прочитать целиком · 2 отметить непонятное · 3 проверить методы · 4 прогнать границы · 5 пересказать своими словами

►► Понятие 3

Граничные случаи

  • пустой массив
  • элемента нет на странице
  • пустой ввод
  • нет сети. Код ломается там, а не на «нормальном» сценарии

►► Пустота — не ответ

Объяснение вместо пустого блока

Проверять надо результат фильтрации, а не исходный массив: пирогов шесть, сладких может быть ноль

const sweet = pies.filter(p => p.kind === "сладкое");
if (sweet.length === 0) {
  menu.textContent = "Сладких пирогов сегодня нет";
  return;
}

►► Вторая граница

querySelector возвращает null

Элемент ищем один раз, кладём в переменную, проверяем. Иначе Cannot set properties of null останавливает весь скрипт

const menu = document.querySelector("#menu");
if (!menu) {
  console.warn("Блок #menu не найден");
  return;
}

►► Шаг 5

Пересказ без имён методов

Плохо: «применяет filter с колбэком». Хорошо: «оставляет только сладкие и пишет их названия через запятую в блок меню»

Переписать понятнее, не меняя поведения. Это требование ТЗ итогового проекта, а не пожелание

►► Правило курса

Теперь у него есть процедура

Пять шагов протокола. Шаг 5 и есть проверка правила

[КОНТЕКСТ]
Я школьник, учебный сайт школьного буфета. Чистые HTML, CSS,
JavaScript — без фреймворков, сборщиков и библиотек.
Функция, которую нужно переписать:
<<< сюда вставить свой код целиком >>>

[ЗАДАЧА]
Перепиши эту функцию так, чтобы её было легче читать.

[ОГРАНИЧЕНИЯ]
- ПОВЕДЕНИЕ НЕ МЕНЯТЬ: на одних и тех же данных обе версии должны
  давать одинаковый результат, включая граничные случаи;
- не использовать приёмы, которых нет в списке выше;
- имена переменных и функций — говорящие, по-английски;
- числа-константы вынести наверх с говорящими именами;
- не длиннее исходной функции больше чем на пять строк;
- const и let, никакого var.

[ФОРМАТ ОТВЕТА]
Сначала список из 3–5 строк: что именно ты изменишь и почему.
Потом один блок кода с функцией целиком. Без пояснений после кода.

[КРИТЕРИИ ПРОВЕРКИ]
1. Прогоняю обе версии на обычном наборе данных — результат совпадает.
2. Прогоняю на пустом массиве — результат совпадает.
3. Прогоняю на граничном значении (ровно порог скидки) — совпадает.
4. Каждое имя в новой версии я могу объяснить, не заглядывая в код.
5. Ни одного метода, которого нет в списке с занятий.

Проверить руками: три набора данных, обе версии · каждый метод есть в списке с занятий · ни одной строки без пересказа · константы вынесены и названы · старая версия сохранена

Правило курса: сдаётся только то, что ты можешь объяснить

Глоссарий занятия 17

Аудит кода
Проверка чужого кода по фиксированному порядку из пяти шагов, прежде чем взять его в проект. Одинаково применяется к коду от ИИ, из интернета и из учебника.
Галлюцинация
Уверенно выданная моделью неправда: несуществующий метод, выдуманный формат ответа API, факт, которого нет. Не выглядит как ошибка: код аккуратный и правдоподобный.
Несуществующий метод
Имя, которого нет в языке: filterBy, mapTo, joinWith, setText. Проверяется в консоли строкой вида [].имя — ответ undefined означает, что такого свойства нет.
TypeError: … is not a function
Сообщение браузера о том, что указанное имя не является функцией. Называет первого виновника; про следующие ошибки браузер молчит, потому что выполнение прервалось.
Граничный случай
Крайняя ситуация, в которой код ломается чаще всего: пустой массив, отсутствующий на странице элемент, пустой ввод, нет сети.
Ранний выход
Приём, при котором функция проверяет проблемную ситуацию в начале и завершается через return, не заходя в основную логику. Убирает вложенные условия и делает код читаемым сверху вниз.
Рефакторинг
Переписывание кода так, чтобы он стал понятнее, а поведение осталось прежним. Если поведение изменилось, это уже не рефакторинг.
Проверка совпадения поведения
Прогон старой и новой версий функции на одних и тех же данных, включая границы. Единственный способ убедиться, что рефакторинг удался.
Магическое число
Число, вписанное прямо в условие или формулу без объяснения: if (total > 300). При рефакторинге выносится в именованную константу.
Пересказ своими словами
Объяснение назначения функции без единого имени метода из кода. Способ проверить понимание, который нельзя обмануть чтением вслух.

Официальный справочник по веб-технологиям. Место, где проверяют не только существование метода, но и то, какие аргументы он принимает.
