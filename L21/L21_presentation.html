list.appendChild(card);

►► Цикл добавления

Пять шагов, порядок не меняется

  • 1 submit на форме
  • 2 preventDefault()
  • 3 .trim()
  • 4 проверка → сообщение и return
  • 5 массив → перерисовка → reset() → focus()
form.addEventListener("submit", (e) => {
  e.preventDefault();
  const title = input.value.trim();
  if (title === "") {
    errorBox.textContent = "Введите название";
    return;
  }
  items.push({ id: String(Date.now()), title: title });
  renderList();
  form.reset();
  input.focus();
});

►► Понятие 3

Нормализация

Чужие пути собраны в одной функции. Дальше весь код работает со своими короткими именами

function normalizeWeather(raw) {
  return {
    city: raw.location.name,
    temp: Math.round(raw.current.temp_c),
  };
}

►► Четыре состояния

Что видит пользователь

  • загрузка — «Загружаем…», кнопка заблокирована
  • успех — данные
  • пусто — объяснение
  • ошибка — фолбэк и честная пометка

►► Обработка сбоя

try — catch — finally

В catch — фолбэк и пометка. В finally — разблокировка кнопки: он выполняется и после успеха, и после ошибки

catch (error) {
  renderWeather(normalizeWeather(FALLBACK));
  statusBox.textContent =
    "Данные из сохранённой копии";
} finally { btn.disabled = false; }

►► ИИ в работе

Первый рефакторинг из двух

Формат API у модели не спрашиваем. Отдаём одно: функцию длиннее двадцати строк — переписать понятнее, не меняя поведения

[КОНТЕКСТ]
Я школьник, делаю учебный проект — веб-панель на чистых HTML, CSS
и JavaScript, без фреймворков и без бэкенда. На занятиях были:
массивы и объекты, filter/map/join/find/sort, циклы for и for...of,
функции, условия, шаблонные строки, querySelector, addEventListener,
делегирование через closest, textContent, classList, валидация форм,
Promise, async/await, try/catch/finally, fetch, localStorage.
Данные хранятся в массиве, интерфейс всегда перерисовывается целиком.

Функция, которую нужно переписать:
<<< сюда вставить свой код целиком >>>

[ЗАДАЧА]
Перепиши эту функцию так, чтобы её было легче читать.

[ОГРАНИЧЕНИЯ]
- ПОВЕДЕНИЕ НЕ МЕНЯТЬ: на тех же данных обе версии дают одинаковый
  результат, включая границы (пустой массив, отсутствующее поле,
  сбой запроса);
- не использовать приёмы, которых нет в списке выше (в частности
  reduce, регулярные выражения, деструктуризацию) — я не смогу
  объяснить такой код;
- не менять имена функций, которые вызываются снаружи;
- числа-константы вынести наверх с говорящими именами;
- не длиннее исходной функции больше чем на пять строк;
- const и let, никакого var.

[ФОРМАТ ОТВЕТА]
Сначала список из 3–5 строк: что именно ты изменишь и почему.
Потом один блок кода с функцией целиком. Без пояснений после кода.
Если данных не хватает — не пиши код, задай не больше трёх вопросов.

[КРИТЕРИИ ПРОВЕРКИ]
1. Прогоняю обе версии на обычных данных — результат совпадает.
2. Прогоняю на пустом массиве — совпадает.
3. Прогоняю при отключённой сети (Network → Offline) — совпадает.
4. Каждую строку новой версии я могу пересказать своими словами.
5. Ни одного метода, которого нет в списке с занятий.

Проверить руками: три набора данных совпали · протокол аудита занятия 17 · имена снаружи не менялись · сбой на месте · старая версия сохранена · каждую строку можешь пересказать

Правило курса: сдаётся только то, что ты можешь объяснить

Глоссарий занятия 21

Источник истины
Массив с данными, единственное место, где хранится состояние проекта. Интерфейс всегда перерисовывается из него целиком; менять разметку в обход массива нельзя.
Полная перерисовка
Приём, при котором после любого изменения данных список рисуется заново целиком, а не правится по частям. Убирает целый класс ошибок: экран не может разойтись с данными.
Формат ответа API
Как на самом деле устроен JSON, который вернул сервис: имена полей, вложенность, что может отсутствовать. Узнаётся открытием адреса в браузере, а не из описания и не у модели.
Нормализация
Приведение чужих данных к своей структуре сразу после получения, в одной функции. Дальше весь код работает со своими короткими именами.
response.ok
Свойство ответа fetch, показывающее, что сервер ответил успешно. Без этой проверки код будет разбирать страницу ошибки как данные.
Четыре состояния интерфейса
Загрузка, успех, пусто, ошибка. Показываются все четыре; молчание не является ответом ни в одном случае.
Фолбэк
Запасные данные в константе, которые показываются при недоступности сервиса, вместе с честной пометкой «данные из сохранённой копии». Подключается одновременно с API, а не после.
Честная пометка
Текст, сообщающий пользователю, что данные не свежие: «данные из сохранённой копии», «данные от 14:32». Молчаливая подмена настоящих данных запасными — обман.
Кэш последнего ответа
Сохранённый последний удачный ответ сервиса, который показывают при сбое вместо константы. Улучшает фолбэк, но не заменяет его: при первом визите без сети кэша ещё нет.
finally
Блок, выполняющийся и после успеха, и после ошибки. Место для действий, которые нужны в любом случае: разблокировать кнопку, убрать индикатор загрузки.
Массив правил валидации
Структура, где для каждого поля описана функция проверки, возвращающая текст ошибки или пустую строку. Позволяет добавить поле, не переписывая обработчик.
