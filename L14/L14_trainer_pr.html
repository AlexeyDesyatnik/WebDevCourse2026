Порог: 7 ситуаций из 9, не меньше 4 найденных нарушений из 5 и принятое описание.

►► РАЗБОР

Глоссарий

Pull Request (PR)
Заявка на перенос изменений из своей ветки в основную, которую сначала читает человек.
Code Review
Чтение чужого кода перед принятием по конкретному чек-листу из пяти пунктов.
Merge (слияние)
Перенос коммитов одной ветки в другую. Техническое действие; PR — процедура вокруг него.
Конфликт слияния
Одну и ту же строку изменили в двух ветках по-разному. Git выкладывает оба варианта и ждёт человека.
Карточка педагога
  • Навык: довести PR до принятия: описание из трёх блоков, ревью по чек-листу, ручное разрешение конфликта.
  • Норматив: 15–20 мин на тренажёр (83-я минута занятия). Scaffolding — инструкция.
  • Типичные ошибки: ветка не отправлена; заголовок Update script.js; новый PR вместо доработки; конфликт «решён» удалением обоих вариантов; оценочное «норм» вместо замечания к строке; строка 5 помечена не тем пунктом чек-листа.
  • Зачёт: тесты 2–10 ≥ 7/9, тест 11 (4 из 5 нарушений с верным пунктом) и тест 13 (описание принято). Три подсказки — зачёт с пометкой «с поддержкой».
  • Усложнение: попросить переформулировать оценочную реплику в формулу «место + что не так + почему».
  • Упрощение: сначала только ситуации 1–5, ревью — пункты 1 и 2, описание по готовому шаблону с пропусками.
  • ИИ: модель — первый ревьюер. Руками: пункт 3 на 320 px в браузере, пункт 5 — устный вопрос автору. Замечание без места выбрасывается.
